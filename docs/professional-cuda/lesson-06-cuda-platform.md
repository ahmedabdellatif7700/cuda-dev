## Core idea

CUDA is a complete programming platform; source language, runtime, driver, compiler, and tools serve different roles.

**Code or evidence:** [CMakeLists.txt](../../CMakeLists.txt). The host compiler builds C++ orchestration, nvcc compiles CUDA, and cudart supports runtime calls. PTX is intermediate code, not a profiling result.

**Original lesson commit:** `1e8f7c0`. This note explains that lesson;
the current main may have advanced to a later experiment.

## Concept

CUDA includes a programming model, runtime/driver APIs, compiler support, libraries,
and development tools. The book also surveys languages, directive-based approaches,
and the ecosystem. Not every historical product or third-party tool is required.

| Layer | Concrete role in this repository |
|---|---|
| Host C++ | Input setup, runtime calls, CPU sum, and printing |
| CUDA language | `__global__`, built-in indices, and `<<<...>>>` launches |
| Runtime API | Allocation, copies, synchronization, launch support |
| Driver | Device/context and code-execution services beneath the runtime |
| Compiler/build | Make → CMake/Ninja → C++ compiler/nvcc → linked executable |
| PTX | Typed intermediate operations generated by `make ptx` |
| SASS | Actual GPU machine instructions, available through `make asm` |
| Tools/libraries | ncu-ui, cuda-gdb, Compute Sanitizer; libraries when later needed |

A `.cu` file can contain host launch wrappers and device kernels. Its extension
does not make all its functions device code. No second implementation is needed:
read one path from `main.cpp` through the wrapper to `VectorAddScalar`.

**Modern correction:** the book says Runtime and Driver API calls cannot mix.
Modern CUDA supports interoperability with context/lifetime rules. We use only the
Runtime API here. See [NVIDIA Driver API documentation](https://docs.nvidia.com/cuda/cuda-programming-guide/03-advanced/driver-api.html).

## Practical reading

Run `make ptx` and inspect `build/assembly/vector_add.ptx`. Relate only loads,
addition, and store to the annotated kernel statement. PTX virtual registers do
not give physical register allocation. The chapter's LLVM/compiler/SDK diagram
is architectural background, not an instruction to replace the existing toolchain.
